Codec.Request/Response use shared Definitions types, not duplicate types. The root
Request has constructors, command/correlation and layout, but no encode/error API.
The root Response has record/payload types and legal response shapes, but no
decode/error API. Root Crc has parameters only and U16 has max only.
Codec.Request/Response expose software functions/errors, not duplicated protocol
constructor namespaces. Use P.Request.Info with P.Codec.Request.encode.
Software helpers that were accidentally public remain available under Codec and
the shim, preserving external compatibility even for low-level helper callers.
Response.shape/shape_length stay on the root because legal command/result/payload
relationships are protocol vocabulary, not byte parsing.

P and W request/response/payload/correlation types, error constructors and derivers
retain identity. Facade removal requires consumer migration and explicit owner
retirement of the frozen archive; source comments document its temporary status.
